## Evening: the learnings store was wiped, twice, by a race that had been running since June

Found while checking the MCP after Yan's reload: `list_learnings since=today` returned the
WHOLE store (2,758 rules, every id new, every `created` = 16:34Z). The 2,808 records of the
morning, `mto8s97bwjfq` and `mt3dxv3668lm` included, were gone. A second wipe at 19:20 local
left 184 records.

Cause, from the code and the audit log: every MCP server watches ~880 doc files (memory files
and session docs included) and on any change re-imports all of them, one full-file rewrite
PER RULE, with `writeFileSync` straight onto `learnings.json`; `loadStore()` turned any
unreadable read into an empty store ("start fresh"). Two or three servers at once (launchd,
VS Code, Claude Code, plus every other project's session through the user-scope entry) made a
torn read a certainty. The audit log shows **54 rebuild bursts since 2026-06-23, 143,352 ids
created for a store of ~2,800**, 11 bursts on 2026-08-21 alone: the same race, for weeks, and
the likeliest source of the audit-chain forks noted in SESSION_23. Every doc edit I made today
triggered it in every running server.

Fix, LOCK `[STORE-NEVER-STARTS-FRESH-OVER-DATA]` (`src/learnings.ts`): atomic writes, an
unreadable file is copied to `.corrupt-<ts>` and the load throws, a shrink below half is
refused, a cross-process lock around every load-modify-save, imports as one batch (one load,
one save for the whole sweep), a daily backup with 7 kept. 10 tests on a throwaway HOME, and a
real race: three separate node processes, 180 concurrent saves on the built code, 300 seeds
intact, nothing torn, no leftovers. Suite 503 green.

Containment done on this Mac: the user-scope Claude Code entry now runs the fixed local build
(`node /Users/yan/Projects/ContextEngine/dist/index.js`, absolute path) instead of the
published 2.5.5; the two old-code servers were stopped; launchd restarted on the fixed build.
Only fixed code writes the store from here. The published 2.5.5 still carries the race: 2.5.6
waits for Yan's GO.

Recovery material, all read-only so far: a safety copy of the 2,758-record rebuilt store
(`learnings.json.post-incident-*`), the 2026-06-08 backup (1,011 records with original ids and
dates, 98 absent today), and every `save_learning` call found in the 138 Claude Code
transcripts (147 distinct, all absent, 139 of them real lessons of 200+ chars). Restoring is a
