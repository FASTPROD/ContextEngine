## 1. The import rule, LOCK `[AUTO-IMPORT-ONLY-MARKED-LEARNINGS]`

Considered and rejected: a section allowlist alone. Sections titled learnings / lessons / rules
still hold 92 records, most of them headings ("Taxonomy walk (Step 3)", "Minimum font size").
The docs are already searchable as docs; the learnings store only has value for what an author
marked as a lesson. So the auto-import (every MCP server, every doc change) now takes only:

1. inline `- [category] rule → context` bullets, anywhere;
2. every shape inside a `*LEARNINGS.md` file (`AGENT-LEARNINGS.md`, `docs/AGENT-LEARNINGS.md`,

3. every shape under a heading (H1, H2 or H3) that says learnings / lessons / gotchas / pitfalls /

queued. Replayed over the 818 sources now discovered: **129 records instead of 1,879**, 1,752
ignored. `import_learnings` gains `permissive: true` and the CLI `--permissive` for a file the user
chose on purpose. Every imported record now carries `source` (absolute path), so this measurement
never has to be re-derived from bursts again. 9 tests in `src/learnings-import.test.ts`.

## 2. Category inference, LOCK `[CATEGORY-BY-WHOLE-WORD-SCORE]`

Measured before touching it: on the 189 store records whose category an agent had chosen by
hand (non-`other`) plus the 14 defaults, `inferCategory()` agreed 21 times, **11.1%**. Cause:
first unanchored substring hit wins. "expose" contains "expo" (mobile), "access" contains "css",
"restart" contains "rest", "build" contains "ui", "login" contains "log". That is how "Scoring
internals are trade secrets, don't expose point values" landed in mobile.

Now: whole-word and whole-phrase matches from a per-category term list, every match counted, a
match in the rule text worth double one in the context, unambiguous technology names worth
double, highest total wins, ties to the more specific category, no match is `other`.
`normalizeCategory()` (section headings) uses the same scorer after an exact category-name match;
"Apple App Store" no longer maps to api on its first three letters.

| Sample | Legacy | Now |
|---|---|---|
| 189 agent-labelled store records + defaults | 11.1% | 27.5% |
| 84 hand-labelled rules (from the 120-record spread sample, noise excluded) | 25.0% | 50.0% |

Both label sets are noisy (agents were inconsistent: "architecture" for a MongoDB timestamp
rule), so the ceiling of a lexicon is low and one pruning pass that looked reasonable lowered
both numbers; it was reverted and tuning stopped there. The hand-labelled sample stays outside
this public repo (`~/.contextengine/category-labels-20260905.json`, it quotes other repos'
notes); `scripts/measure-categories.mjs <labels.json>` reproduces both rows, legacy matcher
included. The committed test uses a generic 36-rule set with an 80% floor plus the substring
regressions above. `[LEARNINGS-LIST-SHOWS-CREATED]` and `[STORE-NEVER-STARTS-FRESH-OVER-DATA]`

## Yan's question: why could two stale servers run unseen? What is monitored, what is not

Measured in the code, not from memory. What CE knows about its own running servers today:
`server-meta.json` holds the tool count and the version of the LAST server to start; nothing
else. `check_ports` reads port declarations in config files, not live sockets. `drift_status`
reads the audit log for loop / stuck-tool / fabrication / silent-failure signals in tool calls,
not processes. `verify-release` proves a freshly spawned server answers with the right version,
not that the servers already running do. Nothing lists the servers that exist, the build each
one loaded, or what each one is doing to the shared store. The two stale ones were found by
`ps`, and only on the second look, because the first grep matched the absolute path only.

Not monitored either, same evening: N Claude Code sessions = N servers = N full re-embeds per
doc change (load average 230 with nine of them); store growth per minute (1,766 in one minute
raised no flag; only shrinking is guarded); records written without a `source`; a doc-change
storm from the session's own edits. See the reply to Yan for the list of what a fleet like this
should watch, and the one mechanism that removes most of it (a single indexing daemon, clients
that read).
