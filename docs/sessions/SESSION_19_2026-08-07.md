# Session 19 — 2026-08-07 — Scorer doc-path bug: `.github/` OR repo root

**Scope**: one bug, fixed at the root. The AI-readiness scorer reported `copilot-instructions.md` and `SKILLS.md` as **Missing** for projects where those files plainly existed — because `scoreProject()` looked only in `.github/`, while `contextengine init` writes `SKILLS.md` at the **repo root** and the generated pre-commit hook accepts either location. The fleet had been working around it by hand-correcting `SCORE.md` rows and `git mv`-ing files into `.github/`.

Continues from [SESSION_18](SESSION_18_2026-06-26.md).

## Trigger

User relayed a report from an earlier session that ended with: *"The real fix belongs in ContextEngine (agents.ts should also check root)"*, then approved the fix with a one-word **"yes"**, then asked **"is the session doc updated and the CE?"** — which produced part D below.

## What was done

### A. Root cause

Two hardcoded paths in [`src/agents.ts`](../../src/agents.ts):

```ts
const copilotPath = join(p, ".github", "copilot-instructions.md");  // line 1087
const skillsPath  = join(p, ".github", "SKILLS.md");                 // line 1138
```

Meanwhile, elsewhere in the same codebase:

| Consumer | copilot-instructions.md | SKILLS.md |
|---|---|---|
| `cli.ts` init (`:430`, `:445`) | `.github/` | **repo root** |
| `cli.ts` freshness check (`:1885`, `:1904`) | `.github/` | **repo root** |
| generated pre-commit hook (`cli.ts:254`) | `.github/` | **repo root** |
| `config.ts` indexer patterns (`:63-65`) | `.github/` | `.github/` |
| `firewall.ts` (`:651`) | `.github/` | — |
| **`agents.ts` scorer** | `.github/` | `.github/` ← **the mismatch** |

So `SKILLS.md` was the genuinely inconsistent one: CE creates it at the root and then scores it as missing. `copilot-instructions.md` is consistently `.github/` across CE — the relayed report's claim that init writes it at the root was inaccurate, but the scorer still deserved the same tolerance since projects legitimately keep it either place.

### B. Fix — `resolveDocPath()` (commit `ffa5914`)

New helper in `src/agents.ts`, `.github/` first, repo root second, carrying a LOCK block:

```
🔒 LOCKED [DOC-PATH-DUAL] — 2026-08-07
⛔ NEVER collapse a caller back to a single hardcoded join(p, ".github", file).
```

Both doc checks now consume it. Score details name the location that was found (`61 lines (.github/copilot-instructions.md)`), and the failure row says `Missing from .github/ and repo root` so the next reader doesn't have to guess which path was consulted. `src/config.ts` `DEFAULT_PATTERNS` also gained root `SKILLS.md` — same mismatch, indexer side.

### C. Impact on the fleet

Projects with root-only `SKILLS.md`, previously scored 0/3 for a file that exists:

`EXO`, `compR.fr`, `invoc.ch`, `VOILA.tips-front`, `GOOGLE Analytics` — up to +13 pts each once re-scored.

ContextEngine itself keeps both docs in `.github/` (moved there in the prior session as the workaround), so its score is unchanged: **88%**. The `git mv` workaround is now obsolete and should **not** be applied to new projects.

Fleet-wide re-score was offered and left to the user — `contextengine score` rewrites `SCORE.md` in ~30 repos, most of which are already dirty from the prior session's run.

The relayed report claimed the bug had been *"saved as a CE learning"*. It had not — a check of `~/.contextengine/learnings.json` (981 rules at the time) found no matching entry. Saved for real this session as `msj4zzi5tgyt` (tooling / ContextEngine).

## Lesson

A scorer that hardcodes one path for a document the same tool writes somewhere else will report "Missing" for files that exist — and the humans reading it adapt by hand-correcting the report, which hides the bug for as long as anyone is willing to do the correcting. The tell was in the workaround itself: *"needed hand-corrections"* after every run is never a docs problem, it's a code problem.

Second lesson, cheaper: a claim that a learning was saved is not a saved learning. `list_learnings` takes two seconds.
